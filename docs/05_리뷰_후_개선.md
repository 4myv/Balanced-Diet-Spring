**2. 예외 처리 세분화**
   - ```java
     @ExceptionHandler(Exception.class)   // 모든 에러의 부모 
     ```
   - 스프링은 원래 형식이 잘못된 요청을 400으로 응답한다.
   - 그런데 기존의 `Exception.class`칸이 해당 예외 처리까지 가로채서 500으로 바꿈
   - 해결
     - 잘못된 형식 예외를 처리하는 칸을 따로 만들어줌
     
       |상황|스프링이 던지는 에러|
       |-|-|
       |JSON 모양이 깨지거나 자료형 불일치|`HttpMessageNotReadableException`|
       |필수 값(`?date=`)이 빠짐|`MissingServletRequestParameterException`|
       |바꿀 수 없는 값(`?date=어제`)|`MethodArgumentTypeMismatchException`|
     - 한 칸에 여러 에러 받기
     - ```java
       @ExceptionHandler({ A.class, B.class, C.class })
       public ResponseEntity<ErrorResponse> handle(Exception e)   
       // 파라미터는 ExceptionHandler 안 클래스를 다 담을 수 있는 공통 부모
       ```
     - 외부 응답이 비어 있을 경우
     - `extractText`는 `candidates`가 항상 있다고 가정했음 → 없으면 → `NullPointerException`
     - 응답받은 걸 한 겹 열 때마다 비어있는지 확인
     - 같은 에러를 네 곳에서 던지기 때문에 에러를 만들어 돌려주는 메서드로 분리
     - ```java 
       throw noAnswer(response);   // noAnswer로 에러를 만들어 받고 여기서 던짐
       ```
     - 칸을 고르는 규칙
       - 스프링은 위에서부터 보는 게 아니라 **가장 딱 맞는 칸**을 고름
       - 그래서 칸의 순서는 동작과 상관없음 (번호는 읽는 사람을 위한 것)
       - **같은 에러를 두 칸이 받으면 서버가 안 켜짐** (`Ambiguous @ExceptionHandler`)
         - 2번 칸에 `HttpMessageNotReadableException` 대신 `HttpServerErrorException`을 잘못 넣었을 때, 3번 칸과 겹쳐서 이 상황이 됐음
     - 사용자에게 보여줄 메시지

       |에러를 쓴 사람|사용자에게|
       |-|-|
       |우리 (`throw new ...("문장")`)|`e.getMessage()` 그대로|
       |스프링, 외부 API|기술적인 내용이라 사람이 읽을 문장으로 바꿔서 보내고, 원래 메시지는 로그에|
     - Gemini가 보낸 에러 나누기

       |Gemini 응답|RestClient가 던지는 것|우리 응답|이유|
       |-|-|-|-|
       |5xx (바쁨)|`HttpServerErrorException`|503|잠시 후 다시 시도하면 됨|
       |429 (사용량 초과)|`HttpClientErrorException`|503|사용자 잘못이 아님, 잠시 후 다시|
       |403, 404 등 (키·모델 문제)|`HttpClientErrorException`|500 + `log.error`|우리 서버 설정 문제라 개발자가 고쳐야 함|
       |답이 없음 (안전 필터 등)|(응답은 오지만 비어 있음)|400|다른 내용으로 다시 시도하면 해결|

   ```java
     if (e.getStatusCode().value() == 429) {
         return ResponseEntity.status(503).body(...);
     }
     log.error("Gemini 요청 오류: {} {}", e.getStatusCode(), e.getResponseBodyAsString());
     return ResponseEntity.status(500).body(...);
   ```

**3. 에러 종류 만들기 - NotFoundException**

   ```java 
    // 찾는 데이터가 없을 때 던지는 에러 -> 404
    public class NotFoundException extends RuntimeException {
    // RuntimeException(런타임 에러)을 상속받는다 -> 언체크 예외(unchecked exception)가 됨
    // 왜 Exception이 아니라 RuntimeException을 물려받냐면,
    // Exception을 바로 상속받으면 체크 예외(checked exception)가 되어,
    // 이 에러를 던지는 메서드를 부르는 모든 곳에서 컴파일러가 try/catch(또는 throws)를 강제한다
    // IllegalArgumentException도 RuntimeException의 자식이라 try/catch 없이 던질 수 있었음

        // 생성자
        public NotFoundException(String message) {
            super(message);
            // message파라미터를 담아 부모 생성자 호출
        }
    }
   ```
   - 체크 예외, 언체크 예외
     
     ||부모|컴파일러|
     |-|-|-|
     |체크 예외|`Exception`|던지는 메서드를 부르는 곳에 try/catch(또는 throws)를 강제|
     |언체크 예외|`RuntimeException`|강제 안 함|    - "없는 기록"은 400(잘못된 요청)이 아니라 404(없는 것)
   - 상황에 맞는 이름의 에러로 400 대신 404를 보내기 위해 직접 만들었음

**4. 외부 API에 시간 제한**
   - 기본 설정은 답이 올 때까지 시간 제한 없이 계속 기다림
   - Gemini 응답이 너무 길어지면 사용자는 로딩만 계속 보게 되고, 서버는 그 요청에 스레드(일꾼) 하나가 묶임
   - 이런 요청이 쌓이면 다른 요청까지 처리 못 하게 됨
   - 두 가지 시간 제한
   
     ||뜻|값|
     |-|-|-|
     |connect timeout|상대 서버와 연결되기까지의 시간|5초|
     |read timeout|연결된 뒤 답이 오기까지의 시간|30초|
   - 코드
   ```java
    SimpleClientHttpRequestFactory requestFactory = new SimpleClientHttpRequestFactory();
    requestFactory.setConnectTimeout(Duration.ofSeconds(5));
    requestFactory.setReadTimeout(Duration.ofSeconds(30));  
    RestClient.builder()
    .baseUrl("...")
    .requestFactory(requestFactory)
    .build();
   ```
   - RestClient = "어떻게 보낼지" 정리
   - RequestFactory = 실제로 연결하고 주고받는 도구
   - `create(주소)` = 기본 주소 지정, 나머지 설정 그대로
   - `builder()`→`build()` = 설정을 붙여서 완성
   - `Duration` = 시간의 길이. 단위가 이름에 드러남(`ofSeconds`, `ofMillis`)
   - 시간 제한을 넘거나 연결이 안 되면 `ResourceAccessException` → 우리 서버에서 504(Gateway Timeout)로 응답

**5. HTTP 상태 코드 정리**

|코드|뜻|프로젝트에서의 역할|
|-|-|-|
|200|성공||
|400|잘못된 요청|값 검사 실패, 형식 오류, AI가 분석 못 한 내용|
|404|찾지 못함, 없음|없는 주소, 없는 기록, 신체 정보 없음|
|500|서버 내부 문제|AI 설정 문제, 그 외|
|503|잠시 이용 불가|Gemini 바쁨, 사용량 초과|
|504|대신 물어본 서버가 답을 안 줌|Gemini 응답 시간 초과|

**6. 로그 수준**

||상황|예|
|-|-|-|
|`log.warn`|예상할 수 있는 문제, 개발자가 당장 고칠 건 없음|Gemini 바쁨, 잘못된 요청 형식, 시간 초과|
|`log.error`|개발자가 확인하고 고쳐야 하는 문제|키ㆍ모델 설정 오류, 예상치 못한 에러|
- `log.warn("메시지: {}", 값)` - `{}`자리에 값이 들어감
- `log.error("메시지", e)` - 뒤에 `e`를 넣으면 에러 전체 내용이 찍힘
